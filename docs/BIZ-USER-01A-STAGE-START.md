## 1. Goal

A user's own workflow is a `user_agents` row that carries the six-part spec (tone, reply language, purpose, procedure, result; access = tool profile, knowledge folders, connector tool ids; model) and a stored budget per run and per day. The owner creates one blank or by copying the Chief of Staff, and edits it. Every grant a run will later use is derived on the server from the stored row intersected with the platform allowlist, never from the browser. Running it is BIZ-USER-01C; the editor is BIZ-USER-01B.

## 3. What is true today

- **The row.** `user_agents`: id, user_id, name varchar(100), role varchar(200), description text, status varchar(20) default 'active', initials varchar(4) null, created_at, updated_at, deleted_at (`services/api-gateway/src/migrations/1772500000000-CreateUserAgentsTable.ts:15-27`; entity `user-agent.entity.ts:14-53`). Statuses `active | draft | disabled` (`:14`).
- **The routes.** `POST /api/agents` (name, role, description required; status and initials optional; `user-agent/dto/create-agent.dto.ts:12-37`), `GET /api/agents`, `GET /api/agents/:id`, `DELETE /api/agents/:id`, all behind `SessionCookieGuard` and scoped by `req.user.userId` (`user-agent.controller.ts:43-88`). No update route. The global `ValidationPipe` has `whitelist: true, transform: true` and no `forbidNonWhitelisted`, so unknown body fields are dropped silently (`main.ts:64-68`).
- **The frontend today** posts `{ name, role, description }` and types the row as id, name, role, description, status, initials, createdAt, updatedAt (`frontend/hooks/useUserAgents.ts:5-14, 130-135`). It must keep working unchanged until 01B.
- **The typed spec (AGENT-SPEC-01).** `SystemAgentPromptSpec` = tone (null or 1-120 chars, no control characters), replyLanguage (`owner | en | zh-TW | zh-CN | null`), purpose, procedure, result, rules (`system-agents/system-agent-registry.ts:52-59`); `SystemAgentAccess` = toolProfile (`read | review | write | null`), knowledgeScopes, connectorToolIds (`:62-66`); `SystemAgentModel` = `{ choice: 'server' } | { choice: 'platform', id }` (`:32-34`). Helpers: `renderAgentInstructions` (`:144-147`), `agentInstructionsWithinLimit` against `MAX_AGENT_INSTRUCTIONS_CHARS` = 4000 (`:150-152`; `orchestration/handoff-request.ts:7`), `isSystemAgentModel` (`:165-181`), `systemAgentPromptSpecProblems` (`:183-206`; shapes only, not length), `neverDoFor(access)` (`:208-240`). The version material and hash are private (`:484-509`). The Chief of Staff draft: tool profile `read`, six knowledge scopes, `[MAIL_TOOL_ID, CALENDAR_TOOL_ID]`, `model: { choice: 'server' }` (`:420-432`). `GET /api/system-agents` returns public rows without instructions, so a copy must be made server-side from `systemAgentById` (`:536`).
- **Models.** `PLATFORM_MODEL_IDS` = the four Anthropic ids, each 1 credit per 1K tokens, `isPlatformModelId` (`system-agents/platform-models.ts:14-19, 35-37`). Runs still take provider and model from env (`orchestration/collaboration.controller.ts:491-499`).
- **Knowledge folders.** The scope catalogue is fixed: nine ids in `knowledge/knowledge-scopes.ts:16-26`, looked up by `findKnowledgeScope` (`:34-36`); `knowledgeScopesJobFields` accepts an explicit id array and throws on a bad or duplicate id, so it cannot be signed (`:67-78`). Documents are stored per owner and scope (`entities/knowledge-document.entity.ts:15-16, 31-32`), and reads filter by `userId` and scope (`knowledge/knowledge.service.ts:87-101`), so a scope already means "the owner's own documents in that folder". - **Connections and grants.** One connection per owner per kind, `connector_connections (user_id, kind)` unique (`entities/connector-connection.entity.ts:18-31`); `ConnectorsService.list(userId)` (`connectors/connectors.service.ts:90-95`). Role tool ids come from the registry (`orchestration/collaboration-tool-profile.ts:82-102`).

- **Migrations.** Latest `1802000000000-CreateConnectorConnectionsTable.ts`. Column-add pattern with a fail-closed probe: `1798000000000-AddCollaborationReferralPendingJob.ts:15-40`. Tests are mocked SQL-shape specs in `migrations/__tests__/`, with a timestamp-ordering test (`1802000000000-...spec.ts:60-69`) and a "no DELETE / TRUNCATE / UPDATE" assertion (`:78`).
