## Objective

Extend the existing `workspaceContext` plumbing introduced in AI-CTX-01 to include the content of the currently selected/open file, capped and safely filtered, so the AI can answer questions about the selected file (e.g. "what are the 4 buttons in index.html for?") without adding named file read, workspace search, file delete, new endpoints, or broad AI tooling.

## Implementation Summary

### `frontend/app/[locale]/app/page.tsx`

- Added `WORKSPACE_CONTEXT_MAX_SELECTED_FILE_CHARS = 8000` constant alongside the existing `WORKSPACE_CONTEXT_MAX_FILE_PATHS = 200`.
- Added module-scope pure `isSensitiveFilePath(path: string): boolean` helper. Returns `true` for paths matching:
  - env/secret/credential files: `.env`, `.env.*`, `*.env`, `*.env.*`, `*.key`, `*.pem`, `*.cert`, `*.secret`, `*.credentials`
  - package lock files: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `*.lock`
  - common binary/asset extensions: `.png`, `.jpg`, `.jpeg`, `.gif`, `.ico`, `.webp`, `.svg`, `.woff`, `.woff2`, `.ttf`, `.eot`, `.mp4`, `.mp3`, `.zip`, `.gz`, `.tar`, `.bin`, `.exe`, `.dll`, `.so`
  - minified/generated: `.min.js`, `.min.css`, `.map`
  - path segments: `/dist/`, `/build/`, `/coverage/`
- Extended `WorkspacePromptContext` interface with optional `selectedFileContent?: string`.
- Extended `buildWorkspacePromptContext(workspaceFileTree, selectedFilePath, selectedFileContent?)`:
  - Existing file path list and selected file path behavior is preserved unchanged
  - Computes `normalizedSelectedFileContent`: included only when `selectedFilePath` is present, `selectedFileContent` is non-empty after trim, and `isSensitiveFilePath(selectedFilePath)` is false
  - Trims content; slices to 8000 chars; appends `\n[...truncated at 8000 characters]` if truncated
  - Returns the content as `selectedFileContent` on the context object when eligible; omits it otherwise
- Updated both AI request-building call sites to pass `selectedFileContent` state as the third argument:
  - `handleSubmitChatPrompt` (direct path, line ~3749)
  - `submitOrchestratedChatPrompt` (orchestrated path, line ~3459)

### `services/api-gateway/src/clients/ai-service-http.client.ts`

- Added `selectedFileContent?: string` to `WorkspaceContext`. One line.

### `services/ai-service/src/queue/job.types.ts`

- Added `selectedFileContent?: string` to `WorkspaceContext`. One line.

### `services/ai-service/src/worker/worker.processor.ts`

- In `buildWorkspaceContextBlock(workspaceContext?)`:
  - Added `normalizedSelectedFileContent`: non-empty string from `workspaceContext.selectedFileContent` when present, else `null`
  - Null guard extended: returns `null` only when file paths, selected path, AND selected file content are all absent
  - Appends a `Selected file content:\n<content>` section after "Currently open file:" when content is non-null
  - Existing no-context and file-paths-only behavior preserved unchanged

Prompt output format when all fields are present:
```
Current workspace files:
- src/app.ts
- index.html

Currently open file:
index.html

Selected file content:
<content here>

Execution output contract:
...

User request:
...
```

## Honest Notes

- `workspaceContext` remains optional and backward-compatible at every layer. If selected file content is absent or excluded by the sensitivity filter, the prior AI-CTX-01 behavior (file path list + selected path only) still applies unchanged.
- No frontend unit test was added for `buildWorkspacePromptContext(...)`. Implementation relied on frontend typecheck plus focused cross-layer and backend tests, as no clean pre-existing frontend test seam for this function existed.
- The change allows the AI to answer selected-file content questions such as "what are the 4 buttons in index.html for?" when that file is selected/open and eligible (not sensitive, not binary, not a lock file).
- Token/cost impact per request: up to ~2000 additional tokens for a typical file at the 8000-char cap.

---

## Preserved Invariants

- Content injection is selected-file-only; no other files are included
- Content is capped at 8000 characters to avoid token/cost blowup
- Sensitive, binary, lock, and generated files are excluded by path-pattern check at the frontend before any content is serialized
- File-action output contract (`create`, `write`, `update`) preserved unchanged; context block is prepended before it, not mixed in
- `workspaceContext` is optional and backward-compatible at every layer
- No container-manager dependency introduced into ai-service worker
- Provider selection and queue execution semantics preserved
- No destructive action support in this slice
