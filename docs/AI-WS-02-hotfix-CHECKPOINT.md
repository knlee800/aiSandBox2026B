## Objective

In `parseStoredChatThreadMessages`, when a restored message has `fileActionState.applyStatus === 'awaiting-confirmation'`, convert it to `applyStatus: 'skipped'` with `skipReason: 'session-restored'` and `confirmationRequired: false`, so the message shows a neutral skipped indicator rather than a non-functional Apply button.

## Implementation Summary

### `parseStoredChatThreadMessages` — post-validation normalization only

The only change is a three-line guard added inside the already-existing `isWorkspaceExecutionFileActionState(...)` branch, after the initial spread and `confirmationRequired` normalization:

```typescript
if (normalizedFileActionState.applyStatus === 'awaiting-confirmation') {
  normalizedFileActionState.applyStatus = 'skipped';
  normalizedFileActionState.skipReason = 'session-restored';
  normalizedFileActionState.confirmationRequired = false;
}
```

**Before:** A message persisted with `applyStatus: 'awaiting-confirmation'` was restored as-is, rendering an Apply button that was non-functional because `pendingConfirmationExecutionIdsRef` is reset empty on every session restore. Pressing Apply silently returned early with no action.

**After:** That same restored message now has `applyStatus: 'skipped'` with `skipReason: 'session-restored'`. The confirmation Apply button does not render. The message shows the neutral "skipped (session-restored)" indicator instead. All live in-session confirmation behavior is completely unaffected — the guard only runs inside the `parseStoredChatThreadMessages` restore path, which is never called for in-session state updates.

All other `applyStatus` values (`'applied'`, `'skipped'`, `'pending'`) are unaffected.
