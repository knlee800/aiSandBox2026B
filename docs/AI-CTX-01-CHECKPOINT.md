## Objective

Make the active AI execution path aware of the current workspace file list and selected file path so non-mutating questions like "list all files" can be answered correctly without adding destructive actions, schema changes, new endpoints, or broad AI tooling changes.

## Implementation Summary

### `page.tsx`

- Added `WORKSPACE_CONTEXT_MAX_FILE_PATHS = 200` constant.
- Added `WorkspacePromptContext` interface at module scope: `{ filePaths: string[]; selectedFilePath?: string }`.
- Added `collectWorkspacePromptFilePaths(nodes, filePathSet)` — recursive helper that walks `WorkspaceFileNode[]` and collects file-only paths into a `Set<string>`, ignoring directories.
- Added `buildWorkspacePromptContext(workspaceFileTree, selectedFilePath)` — returns `WorkspacePromptContext | undefined`. Dedupes and sorts file paths, caps at 200, includes `selectedFilePath` when non-empty. Returns `undefined` when both are absent.
- In `handleSubmitChatPrompt` (direct path): derives `workspaceContext` immediately before the `/api/ai/execute` fetch body; spreads `{ workspaceContext }` into the request body only when defined.
- In `submitOrchestratedChatPrompt` (orchestrated path): same derivation and spread inside the per-step fetch body.

### `services/api-gateway/src/clients/ai-service-http.client.ts`

- Added exported `WorkspaceContext` interface: `{ filePaths: string[]; selectedFilePath?: string }`.
- Added `workspaceContext?: WorkspaceContext` to `AIExecutionRequest`.

### `services/api-gateway/src/ai/ai-execution.controller.ts`

- In `queueService.enqueueExecution(...)` call: added `workspaceContext: request.workspaceContext` — passes through unchanged; `undefined` when not present.

### `services/ai-service/src/queue/job.types.ts`

- Added `WorkspaceContext` interface: `{ filePaths: string[]; selectedFilePath?: string }`.
- Added `workspaceContext?: WorkspaceContext` to `AiExecutionJob`.

### `services/ai-service/src/worker/worker.processor.ts`

- Added `import type { WorkspaceContext } from '../queue/job.types'`.
- Added `buildWorkspaceContextBlock(workspaceContext?)` — pure function. Normalises and validates path strings. Returns a formatted prompt section string or `null` when context is absent or empty:
  ```
  Current workspace files:
  - path/to/file-a
  - path/to/file-b

  Currently open file:
  path/to/file-a
  ```
- Extended `buildExecutionPromptWithFileActionContract(userPrompt, workspaceContext?)` (now exported) — when context block is non-null, prepends it before the file-action output contract; when absent, output is byte-identical to prior behaviour.
- Updated the call site inside the worker job loop to pass `job.data.workspaceContext` as the second argument.

## Honest Notes

- `workspaceContext` is optional and backward-compatible at every layer — callers that omit it receive a prompt identical to prior behaviour.
- File paths are capped at 200 to control token/cost growth.
- No file contents are included; this is path-list context only.
- This enables non-mutating file-awareness requests like "list files" without introducing destructive action support.
