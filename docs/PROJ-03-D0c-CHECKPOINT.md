# PROJ-03-D0c CHECKPOINT

## Task Metadata

- **Task ID:** PROJ-03-D0c
- **Title:** Load Project List In Project-First No-Session Entry Path
- **Nature:** FRONTEND / LOAD-PATH WIRING
- **Status:** COMPLETE and LOCKED
- **Checkpoint:** `docs/PROJ-03-D0c-CHECKPOINT.md`
- **Source:** Post-D0b diagnostic: `loadWorkspaceProjectsForUser(token)` was only invoked from the `[selectedSessionId]` effect which early-returns when `selectedSessionId` is null; on project-first entry there is no session yet so the project picker appeared empty even though projects exist in the database
- **Depends on:** PROJ-03-D0b (COMPLETE and LOCKED)

## Objective

Behind `PROJECT_FIRST_UX`, ensure the existing project picker is populated on first entry even when no session is selected, by calling the user-scoped project list loader from the token/bootstrap path rather than relying only on the session-keyed effect.

**`frontend/app/[locale]/app/page.tsx` was the only production file changed.**

## Locked Scope Actually Implemented

This is a load-path wiring change only. All handler semantics, backend calls, route structure, session-keyed effect, and legacy code paths are untouched.

### `frontend/app/[locale]/app/page.tsx`

Added a small `PROJECT_FIRST_UX`-gated block to the existing bootstrap effect (deps `[locale, router]`), after the existing calls to `loadSessions(token)` and `loadDashboardSlice(token)`:

```ts
if (PROJECT_FIRST_UX) {
  void loadWorkspaceProjectsForUser(token);
  void loadPublicWorkspaceProjectsList();
}
```

The block is placed at lines 467–470, inside the same bootstrap effect (lines 450–471) that already runs on first mount when a token is present.

**Before D0c:** `GET /api/projects` was only triggered by the `[selectedSessionId]` effect (lines 523–587), which early-returns when `selectedSessionId` is null. On project-first entry with no session selected, `workspaceProjects` stayed `[]` and the project picker dropdown was empty.

**After D0c:** When `PROJECT_FIRST_UX` is true and a token is present, `loadWorkspaceProjectsForUser(token)` is called immediately in the bootstrap path. The project list populates the picker before any session is created or selected.
