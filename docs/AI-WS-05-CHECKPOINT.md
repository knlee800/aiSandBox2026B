## Implementation Summary

- AI-WS-05 adds bounded named-file context to the existing `workspaceContext` pipeline.

### `frontend/app/[locale]/app/page.tsx`

- Added `WORKSPACE_CONTEXT_MAX_NAMED_FILES = 3`
- Extended `WorkspacePromptContext` with:
  - `namedFileContents?: Array<{ path: string; content: string }>`
- Reused the existing sensitive/unsuitable path filter
- Reused the existing 8,000-character truncation cap
- Added conservative explicit path matching against current `workspaceFileTree`:
  - full path match from prompt
  - quoted/backticked path match through same explicit reference matching
  - basename match only when basename is unique in the workspace
- Limited matched files to existing workspace file paths only
- Read matched files with existing `readWorkspaceFile(...)` helper
- Skipped unreadable files without failing the AI request
- Wired the new async `workspaceContext` build into both AI submit paths:
  - direct submit
  - orchestrated submit

### Cross-layer plumbing

- `services/api-gateway/src/clients/ai-service-http.client.ts` now accepts `namedFileContents` in `WorkspaceContext`
- `services/ai-service/src/queue/job.types.ts` now accepts `namedFileContents` in queue `WorkspaceContext`
- `services/ai-service/src/worker/worker.processor.ts` now appends each block as:
  - `Named file content: <path>`
  - followed by bounded content

---

## Explicit Bounding / Invariants

- Only matches paths already present in current `workspaceFileTree`
- No arbitrary path reads
- No file-content search
- No workspace search support
- Basename matching only when unique
- Maximum 3 files per prompt
- Each file capped at 8,000 characters with truncation marker
- Sensitive/env/binary/lock/generated files excluded before read/injection
- Existing context preserved:
  - workspace file path list
  - selected file path
  - selected/open file content
  - project/workspace metadata
- File-action behavior unchanged:
  - no file-action schema changes
  - no parser changes
  - no AI delete behavior changes
