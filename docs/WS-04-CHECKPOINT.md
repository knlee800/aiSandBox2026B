## Implementation Summary

### `workspace-workspaces.logic.ts` (new)

`Workspace` type matching current backend response shape:

| Field | Type |
|---|---|
| `id` | `string` |
| `userId` | `string` |
| `name` | `string` |
| `slug` | `string` |
| `isDefault` | `boolean` |
| `createdAt` | `string` |
| `updatedAt` | `string` |

Helper functions added (all follow the existing `fetchImpl`-injectable, `Authorization: Bearer`, `response.ok` / JSON parsing conventions used throughout the repo):

- `loadWorkspaces(args: LoadWorkspacesArgs)` — `GET /api/workspaces`
- `loadWorkspace(args: LoadWorkspaceArgs)` — `GET /api/workspaces/:id`
- `createWorkspace(args: CreateWorkspaceArgs)` — `POST /api/workspaces`
- `updateWorkspace(args: UpdateWorkspaceArgs)` — `PATCH /api/workspaces/:id`
- `deleteWorkspace(args: DeleteWorkspaceArgs)` — `DELETE /api/workspaces/:id`; returns `{ deleted: true }`

### `workspace-projects.logic.ts` (updated)

- `WorkspaceProjectSummary`: added required `workspaceId: string | null`
- `CreateProjectArgs`: added optional `workspaceId?: string`
- `createWorkspaceProject`: includes `workspaceId` in POST body only when provided and non-empty
- Public project list/detail types (`WorkspacePublicProjectSummary`, `WorkspacePublicProjectDetail`) left unchanged — current backend public endpoints do not return `workspaceId`
- `forkPublicWorkspaceProject` return type narrowed from `WorkspaceProjectSummary` to new `WorkspaceForkedProjectSummary` (`{ id, name, visibility: 'private', createdAt, updatedAt }`) to match the current backend public fork payload shape

### Tests

- `workspace-workspaces.logic.test.ts`: 5 tests — one per helper — all pass
- `workspace-projects.logic.test.ts`: 9 tests — updated fixtures for `workspaceId`; two new cases for create-with-explicit-workspace and create-without-workspace — all pass
- `workspace-shell.test.tsx`: 3 typed `WorkspaceProjectSummary` fixture objects updated with `workspaceId: null` to satisfy the new required field; no test logic changed
