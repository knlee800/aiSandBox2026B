## Implementation Summary

AI-WS-06 adds bounded workspace text search.

### Container-manager

- Added a plain-text workspace search endpoint under the existing files surface.
- Implemented Node filesystem traversal, not shell.
- Searches only the current session workspace.
- Returns structured results:
  - `query`
  - `results: Array<{ path, line, preview }>`
  - `truncated`

### API gateway

- Exposes `POST /api/sessions/:id/files/search`.
- Uses the same owned-session and terminated-session guards as the other session file routes.
- Proxies the narrow plain-text query to container-manager.

### Frontend

- Added `searchWorkspaceFiles(...)`.
- Added conservative prompt search-intent/query extraction in `page.tsx`.
- Only runs search for explicit locate/find/search style prompts.

### `workspaceContext`

- `searchResults` now flows frontend -> api-gateway -> ai-service worker.

### AI prompt

- Appends compact search results as:
  - `Workspace search results for: <query>`
  - `- path:line - preview`
  - `[...results truncated]` when capped

### Existing context preserved

- file list
- selected file path
- selected file content
- named file contents
- project/workspace names

## Explicit Bounded / Safe Behavior

- Current workspace/session only
- Plain text query only
- No model-controlled shell/exec path
- Explicit prompt intent only; search is not run on every prompt
- Query cap: 120 chars
- Files scanned cap: 200
- Match cap: 20
- Preview cap: 240 chars
- Total returned search payload cap: about 8,000 chars
- Additional file read cap: files larger than `262144` bytes are skipped
- Invalid/unsafe queries fail closed
