## 1. Goal

A user's own workflow (a `user_agents` row from BIZ-USER-01A) runs from the Team page as a team of one, through the same signed collaboration path a Chief of Staff run uses. The gateway renders the prompt and derives every grant from the stored row; nothing of the spec comes from the browser. A workflow must pass a test run before it runs normally (C13). A run is refused at start when the workflow's budget is used up (C15). The six-part fields and grants never reach `POST /api/ai/execute`.

The query loads the workflow's completed referrals and filters in code (small per workflow). See DECISION A. |
| D8 | **Budget refused at start (C15).** Both checks run at start (D2) and again at approve, inside the workflow branch before `assertHandoffAllowed`, because credits can be spent during the wait. **Per day:** `spentToday` = SUM(`requested_credits`) of `credit_deduction_records` where `owner_id` = user, `source_event_id` ∈ the execution ids of this workflow's referrals, `created_at` ≥ 00:00 UTC (the platform cap's day and unit, `daily-credit-cap.service.ts:19, :87-91`); `spentToday >= budgetPerDayCredits` → 429 `WORKFLOW_BUDGET_DAY { budget, spent }`. **Per run:** no mid-run cutoff exists (section 2), so the per-run budget is checked against the workflow's own last completed run: `lastRunCredits` = requested credits of the most recent completed run's execution; `lastRunCredits > budgetPerRunCredits` → 409 `WORKFLOW_BUDGET_RUN { budget, lastRun }`.
